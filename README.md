# CarClip 導線監視

car-clip.com の「LP → 商品ページ → カート」の導線が壊れていないかを、
**実際のブラウザ（Chromium）でJavaScriptを実行しながら** 2時間ごとに検査し、
異常があればメールで通知します。

2026年7月に発生した「`$ is not a function` でLPの車種セレクターが停止し、
広告費だけ消えて売上がゼロになる」事故と同じ種類の障害を検出することが目的です。

---

## 何を検査するか

各ページについて、以下を順に確認します。

| # | 検査 | 検出できる障害の例 |
|---|------|-------------------|
| 1 | HTTPステータスが200か | ページ消滅、500エラー、リダイレクト事故 |
| 2 | 致命的なJavaScriptエラーが出ていないか | **今回の `$ is not a function`** |
| 3 | 必須テキストが表示されているか | テンプレート破損、白画面 |
| 4 | 商品リンクが規定本数以上あるか | 商品が消えた、リンク生成の失敗 |
| 5 | 商品リンクが実際に開けるか（ランダム抽出） | リンク切れ、404 |
| 6 | JS生成セレクターを実際にクリックできるか | **今回の車種セレクター停止** |
| 7 | カートに商品を投入できるか | カートボタン消失、Welcart破損 |

**#2 と #6 が本命です。** 通常の死活監視（HTTPステータスだけ見るタイプ）では、
今回の障害は「HTTP 200 が返っている」ため一切検知できませんでした。

### 注文は発生しません

カート投入テストはセッション上でカートに入れて中身を確認するだけで、
**注文確定は一切行いません**。売上データや在庫には影響しません。
不要なら `config.json` の `cartCheck.enabled` を `false` にしてください。

## 設置手順

### 1. リポジトリを作る

GitHub で `carclip-monitor` という名前の空リポジトリを作成します。
**Public を推奨**します（Private だと GitHub Actions の無料枠を消費します。
このリポジトリにパスワード等は一切含まれません）。

### 2. ファイルを置く

このZIPの中身をリポジトリ直下にドラッグ＆ドロップでアップロードします。
`.github` フォルダも忘れずに含めてください。

```
carclip-monitor/
├── .github/workflows/monitor.yml
├── config.json
├── monitor.mjs
├── package.json
├── state.json
├── .gitignore
└── README.md
```

### 3. APIキーを登録する

リポジトリの `Settings` → `Secrets and variables` → `Actions` →
`New repository secret` で、次の1件を登録します。

| 名前 | 値 |
|------|-----|
| `RESEND_API_KEY` | Resend の APIキー（`re_` で始まる文字列） |

直リンク：`https://github.com/<あなたのアカウント>/carclip-monitor/settings/secrets/actions/new`

### 4. 送信元と宛先を設定する

`config.json` の `alert` を編集します。

```json
"alert": {
  "from": "CarClip監視 <alert@inumachi.com>",
  "to": ["k.morita@tan3.shop"],
  "subjectPrefix": "[CarClip監視]"
}
```

**`from` は Resend でドメイン認証済みのアドレスにしてください。**
`car-clip.com` を Resend に登録していない場合は、認証済みの `inumachi.com` を
そのまま使えます。`to` は配列なので、複数人に送れます。

### 5. 手動で1回動かす

`Actions` タブ → `CarClip 導線監視` → `Run workflow` を押します。
`異常が無くてもレポートメールを送る` を ON のまま実行すると、
**全ページの検査結果がメールで届く**ので、動作確認とベースライン把握が同時にできます。

以降は2時間ごとに自動実行されます。

---

## メールが届くタイミング

無駄なメールで慣れてしまわないよう、送信は絞ってあります。

- **新しく異常が発生したとき** → すぐ届きます
- **異常が続いている間** → 再送しません（既に通知済みのため）
- **異常が解消したとき** → 「復旧しました」が届きます
- **すべて正常なとき** → 届きません
- **手動実行したとき** → 結果に関わらず届きます

前回の状態は `state.json` に記録され、実行のたびに自動でコミットされます。

---

## 監視するページを増やす・減らす

`config.json` の `pages` 配列を編集するだけです。

```json
{
  "name": "新しいLP",
  "url": "https://car-clip.com/newlp/",
  "mustContainText": ["必ず表示されるはずの文字"],
  "productLinkPattern": "^https://car-clip\\.com/newlp[0-9]+/?$",
  "minProductLinks": 3
}
```

| 項目 | 意味 |
|------|------|
| `mustContainText` | ページ上に必ず出るはずの文字列。空配列`[]`なら検査しない |
| `productLinkPattern` | 商品ページURLの形（正規表現）。`null` なら検査しない |
| `minProductLinks` | この本数を下回ったら異常とみなす |
| `interactive` | JSで動くセレクターを実際にクリックさせたいとき |

`interactive.stepTexts` には、順にクリックさせたいボタンの**表示文字**を並べます。
セレクターの選択肢が変わったらここも直してください。

---

## 実行頻度を変える

`.github/workflows/monitor.yml` の cron を編集します。

| 設定 | 頻度 | 月あたりの実行時間の目安 |
|------|------|------------------------|
| `0 */2 * * *` | 2時間ごと（初期値） | 約 700 分 |
| `0 * * * *` | 1時間ごと | 約 1,400 分 |
| `*/30 * * * *` | 30分ごと | 約 2,800 分（Publicリポジトリ推奨） |

Private リポジトリの無料枠は月2,000分です。Public なら無制限です。

---

## うまく動かないとき

**メールが届かない**
`Actions` の実行ログに `RESEND_API_KEY が未設定` と出ていればシークレット登録漏れです。
`メール送信失敗` と出ていれば `alert.from` のドメインが Resend で未認証です。

**正常なのに異常と通知される**
`config.json` の `minProductLinks` が実態より多すぎるか、
`productLinkPattern` が実際のURL形式と合っていない可能性があります。
実行ログに「商品リンク ○本」と出るので、その数字に合わせて下げてください。

**`interactive` のクリックが失敗し続ける**
セレクターのボタン文字が変わった可能性があります。`stepTexts` を実際の表示に合わせるか、
`interactive` ブロックごと削除すれば、その検査だけ無効になります。
